- 2026-06-15 — Prompt caching FIXED (earlier "0 tokens on this account tier" diagnosis was WRONG). Live probe via client.messages.with_raw_response confirmed cache_control was correctly serialized and the request was well-formed. Real root cause: per-model minimum cacheable prefix. Sonnet/Opus min = 1,024 tokens (our 1,338-token system prompt cleared it — caching always worked on them once probed). Haiku 4.5's effective min is ~4,096+ tokens (empirically: no cache at 3,980, cache at 5,672), well above the documented 2,048. Fix: extended SYSTEM_PROMPT to ~2,274 tokens with genuinely useful content (more few-shot theme examples, edge-case handling rules, a final self-check section) — now caches on Sonnet + Opus, verified live (cache_read=2274 on second call). DECISION: did NOT pad to ~4,500 tokens for Haiku — that would be filler and would raise cost on every cache miss; Haiku input is already cheap ($0.80/MTok) so cache savings there are marginal. Caching is enabled where it matters (the expensive models).
